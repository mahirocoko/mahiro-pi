# Managed memory

[← Feature guide](README.md) · [Historical recall](continuity.md) · [Installation](getting-started.md)

## At a glance

Maintained knowledge has one private Markdown/Git owner, separate from historical
quotes and product source. Core/index projection supplies committed context;
relevant detail stays selectively readable rather than flooding every prompt.

- `agent_memory_read`: read/list scoped files, or bounded lexical `query` / pageable
  `topic` discovery. These modes are mutually exclusive, not semantic/vector search.
- `agent_memory_edit`: make a hash-guarded private proposal, not a direct live edit.
- `agent_memory_commit`: integrate a reviewed draft against its base revision;
  successful integration refreshes primary context on a later request.
- `agent_memory_manage`: status, explicit absent-root initialization, conflicts,
  logical forgetting and guarded recovery. Forgetting is not secure Git erasure.
- `agent_memory_reflect`: assign the locked native writer with an identity-bound
  scoped private view; a submitted assignment is not a completed save.

Read before mutation and keep source citations/revisions explicit. Main may share
relevant maintained knowledge across canonical projects; actual workers remain
scoped. Missing exact-root authority fails closed. Installation never imports or
reseeds an existing persona/corpus. See [retrieval details](#bounded-discovery-lexical-retrieval-and-curation-t217-source-slice)
and [roles](agents.md).

The retrieval/curation, bounded late-episode selection, latest-attempt observation
and primary delegation-guidance slices are source/Faux capability, not installed activation, semantic-learning efficacy or companion acceptance. The five tools
and ABI1 remain unchanged. Current work acceptance stays with the human/live board;
the dated migration account below is not a task-status ledger.

## Required behavior

1. **Maintained memory:** readable Markdown Core, an index, deferred project/domain
   knowledge and separately owned procedural memory. Core may include identity,
   user preferences and learned methods; do not restrict the target to operational
   lessons. Preserve established identity and current user/repository instructions.
2. **Main self-edit:** the primary agent can read, add, revise, remove and commit
   maintained knowledge through root-scoped operations. Existing entries should
   be updated rather than accumulating contradictory instructions.
3. **Background writing:** native memory/reflection workers maintain that same
   knowledge through isolated, leased views and integration. They are real
   writers, not literal-quote extractors. Automatic nonconflicting integration is
   supported; semantic Main approval is not mandatory for every edit.
4. **Episode evidence:** reflection can use bounded observed input, assistant
   action, selected tool result, correction and outcome, with durable progress.
   No imported transcript becomes a current instruction or authenticated human
   statement merely because it has a user role.
5. **Context feedback:** a committed memory revision changes subsequent primary
   requests and fresh sessions through public hooks. Do not claim saving or Git
   success alone proves active context. Load Core and discovery metadata, not
   the complete archive or every deferred file.
6. **Maintenance/recovery:** version checks, deduplication/replacement support,
   source-linked forgetting, conflict preservation, cancellation/revocation and
   bounded retry/checkpoint behavior. No recovery may silently resurrect forgotten
   active knowledge. Logical forgetting is not secure erasure of Git/history.

## Layout, tools and lifecycle

Implementation owners are `lib/agent-memory/store.ts`, `runtime.ts`, the derived
`retrieval.ts` schema/parser/search/discovery helper, loaded `guidance.ts`,
`extensions/mahiro-agent-memory.ts` and the package-owned writer role. There is no
runtime import from Mods, installed host internals, or a separate SDK LLM driver.
Root `lib/guards/index.ts` owns the separate `managedMemory` ABI1 on healthy
nodes; public subagents alone runs children and the public permission service
alone resolves policy. The 2026-10-19 private memory activation is distinct from
the separately approved 2026-10-20 Root guard cutover. The current private runtime
registers one Root guard owner and Root public packages, not the legacy guard.
Neither cutover changes exact-root memory grants or establishes human acceptance.

The private root defaults to `<canonical-agent-dir>/memory` (`~/.pi/agent/memory` for the default profile); `MAHIRO_AGENT_MEMORY_ROOT` is an
explicit controlled-store override, not authority. `config.json` is private,
untracked configuration with exact canonical CWD/project mappings, budgets and
`automatic`. Core/index are always-loaded global shared knowledge;
`global/<name>.md` is selectively read shared detailed knowledge;
`deferred/<project>/<name>.md` has preserved project ownership, shared Main access and scoped worker access;
`procedures/<name>.md` is shared procedural knowledge. Global detail and procedures
use the same explicit shared scope as Core/index, not another project's scope.
A custom bootstrap can supply an explicit identity; one-install creates a neutral absent-root scaffold, never an invented human persona. Existing private migration/identity is preserved. No bootstrap corpus or archives are imported automatically. Core supports persona, preferences and learned methods.

Tracked Markdown and `.memory.json` form a standalone private Git repository.
HEAD is the publication boundary. Config, `.views`, `.episodes` and `.lock` are
ignored there. Draft views contain actual scoped Markdown files plus private CAS
metadata. Files/root use 0600/0700; symlinks, hardlinks, escaping paths, secret
patterns, malformed metadata and linked Git metadata fail closed. Git uses fixed
argv, shell=false, exact cwd, 10-second per-command bounds and inherited identity/
hooks. It never changes Git configuration or bypasses hooks. Dirty/staged tracked
work and colliding untracked files block integration instead of being overwritten.
Hook failures preserve the proposal/worktree and leave committed context unchanged;
inspect and recover explicitly rather than bypassing validation.

Default budgets remain Core 8192 bytes, index 2048, each global/deferred/procedure
8192, all knowledge 65536. Explicit private configuration can raise these to
32768/8192/262144/8388608 respectively; 4 KiB is not a native SDK limit. At most
**512 maintained files including Core and index**, across all mapped projects,
are supported. The project-mapping cap remains 128, with 32 source links/file,
4096 forget/review entries, 64 retained views and 256 episode files. The serialized
ledger has an independent 131072-byte ceiling: maximum file/source/tombstone counts
are not a promise that every combination fits that metadata budget.

A private view contains both scoped base and proposed knowledge. Its fixed
**40-MiB serialized ceiling** is checked before any view-file write and by every
full reader and lightweight header reader. Both copies and their ledger metadata
are validated. Allowed text expands by at most 2x in JSON; the executable bound
is `4 * 8388608 + 2 * 131072 + 64 * 512 + 1024 = 33850368` bytes, below the fixed
ceiling. Exact serialized-byte rejection remains authoritative. Publication also
preflights the committed-state view before changing Git; capacity rejection does
not publish an unreadable revision or overwrite the prior proposal.

Inspection and cleanup retain bounded lightweight headers, hydrating only one
selected body at a time. Older view ordering falls back to one validated body,
not a retained array of corpora. A header never authorizes deletion: cleanup
rehydrates and checks the selected full proposal first. Closed/expired nonconflict
views are reclaimed at 32 views; conflicts remain until explicit discard and block
capacity rather than being lost. Fixed ceilings, rather than shrunken current
budgets, validate retained conflicts for listing/discard; stale config hashes
still block active use/publication. Reviewed/forgotten episodes are reclaimed at
capacity; unreviewed evidence is not evicted. Git metadata retains its 8192-entry
ceiling. These are bounded cooperative limits, not secure erasure or an OS sandbox.
Operator maintenance is required at ledger/history capacity; there is no infinite
unattended retention promise.

Main tools:

- `agent_memory_read`: mutually exclusive legacy list/path, lexical query and topic
  modes, all inside the same authenticated view. Returns explicit view basis,
  base/current revisions and freshness; path/query supply whole-file hashes and
  source IDs. The selector/paging contract is detailed below.
- `agent_memory_edit`: add/replace/remove in a private draft with exact file hash
  (`null` for a new file), text and episode source IDs. Core/index cannot be removed.
- `agent_memory_commit`: filewise three-way CAS against the base revision. Disjoint
  file edits merge; overlapping edits preserve a conflict, not a semantic auto-merge.
- `agent_memory_manage`: new-root `initialize` with explicit core/projectId and
  optional automatic flag; status/cancel; revision-guarded forget/rollback/discard;
  bounded conflict listing/proposal inspection. Initialization still requires the
  separate existing exact-root permission and refuses any existing root.
- `agent_memory_reflect`: a bounded explicit assignment to the same native writer
  used by configured automatic reflection. No caller role/model/root/lease flag.

Automatic reflection is controlled by private `automatic` policy; one-install selects true for a new neutral root and preserves existing policy. Startup never enables it. Observed interactive/RPC input
must still match one newly appended native user entry; it is not authenticated
human identity. Episodes retain bounded assistant text/tool names, selected local
check outcomes/results, branch-linked entry hash and observation time. They omit
reasoning, tool arguments, arbitrary reads/recall payloads and imported transcripts.
Only narrow `pnpm check/test` and `node --test` commands contribute selected result
text. Sensitive/oversized/uncertain capture is rejected or omitted. Source screening
is not semantic truth or complete secret detection. Pending episodes survive
sessions; only successful native completion/integration advances reviewed IDs.

### Bounded late-episode selection (T217 P3 source slice)

Input remains exact, nonempty, at most **2048 UTF-8 bytes**, from interactive/RPC
input without images and matching exactly one newly observed native user entry.
There is no input truncation, safe-prefix recovery or longer-input support. The
original session/entry-derived ID, source label, entry hash, branch and completion
checks remain in force; observed user role is not authenticated human identity.

Actions and selected verification results independently retain the **first eligible
plus latest three eligible** records, in original order: six eligible records yield
`[1, 4, 5, 6]` in each array. This is deterministic bounded selection, not semantic
ranking, command/result pairing or episode/session replay. Assistant text and result
text are screened as a complete combined text aggregate before selection: nonempty
oversized, secret-pattern or import-wrapper text rejects that candidate entirely.
There is no pre-screen truncation, individual safe-block salvage or metadata-only
fallback from rejected text that could evict safe evidence. Truly text-absent safe
metadata remains eligible. Assistant tool names require a string, the existing
lowercase/underscore syntax and secret screening before the eight-name cap. Raw
arguments, reasoning and arbitrary read/recall results remain excluded.

Selected results require a previously allowlisted verification call ID and a `bash`
ending. A matching ending consumes its pending ID once, including when its tool
name or text is rejected, so duplicate endings cannot crowd evidence. At most **64
pending verification IDs** are tracked; new starts at capacity are skipped, not
replayed later or allowed to evict earlier pending IDs. Matching endings free
capacity. The command allowlist is unchanged.

Before recording, the runtime checks **UTF-8 bytes of `JSON.stringify(episode)`
plus its persisted newline ≤16384**, including JSON escaping. If needed it removes
whole oldest interior results, then whole oldest interior actions, preserving exact
input and the first/latest action and first/latest result when present. Endpoint
preservation is conditional: if that protected subset still does not fit, capture
is rejected. Fields are never silently sliced, arrays are not cross-paired and the
store's final structural/secret validator remains authoritative. This avoids
writing evidence that the same capped reader cannot reopen.

Fictional event regressions check stored evidence and the writer's exact episode
order, late correction/failure-to-pass, eligibility-before-eviction, typed/secret
tool names, one-shot/capped result matching and escaped-byte/readability bounds.
They also exercise existing input/branch/abort/noncompletion/revocation fences;
the wider suites retain ownership of CAS, forgetting, review cursors and native
worker lifecycle. No guard, format/schema, role, ABI, tool or timeout contract is
changed. These checks prove source behavior, not actual provider learning or
successful real-store reflection. Actual deadline-cause/config diagnosis, exact/current
backlog, longer inputs, deeper P3 consolidation/replay and P4/P5 remain deferred.

A writer has an isolated 120-second view and eight native turns. Its tools cannot
read another project, run Bash or write product/HOME files. Commit marks readiness;
the parent integrates only after actual completed service status, healthy matching
generation/permissions/branch/config and native session-file binding. Foreground
input, session navigation/shutdown, cancellation, expiry and revocation invalidate
publication. Failed/conflicting jobs do not advance review progress. There is no
idle retry/inference loop; pending evidence is retried on a later qualifying turn
or explicit assignment. Main drafts have ten-minute leases and per-file CAS.

### Latest native attempt observation (T217 source slice2)

Existing authorized primary `agent_memory_manage {action: "status"}` additionally
returns `latestAttempt`: `null` before any dispatch or after reset/scope mismatch,
otherwise one ephemeral local observation retained after job cleanup. A new dispatch
replaces it; it is not durable history, completion truth or another store/ledger.
The private `runtime.status()` helper remains unchanged. Existing status fields,
five tools/arguments, ABI1 and policy authority remain unchanged.

The observation exposes only:

- `phase`: `queued`, `running`, `terminal` or `unknown`; `nativeStatus`: one of
  `queued`, `running`, `completed`, `aborted`, `stopped`, `error` or `unknown`.
  These are selected from the exact owned service record after validating its ID
  and writer type, never copied from event payloads. Missing, malformed or throwing
  getters produce `unknown`, not inferred queue/running/success evidence.
- `outcome`: `pending`, `integrated`, `conflict`, `native-unsuccessful`, `not-ready`,
  `integration-unavailable`, `deadline`, `cancelled` or `dispatch-failed`.
  `integrated` requires this parent's successful `store.integrate`; completed native
  execution alone is insufficient. Conflict preservation, unsuccessful native status,
  completed-without-ready and failed integration remain distinct. Existing coarse
  `lastError` categories are retained for compatibility; raw exceptions are not output.
- `dispatchedAt`, `observedAt`, `deadlineAt`: finite bounded local epoch-millisecond
  observations and the earlier local lease/dispatch deadline, not actual queue exit,
  provider start/end or measured execution durations. Native `startedAt` is not used.
- `selectedEpisodeCount` (0–4) and `backlog: {total: null, selectedLowerBound: n,
  selectionLimit: 4, fileCapacityLimit: 256}`. These describe only the existing
  **dispatch selection**. They are neither total nor current unreviewed backlog;
  zero selected episodes on an explicit assignment does not prove an empty store.
  No extra episode scan or store method is added. Selection remains unchanged after
  integration/review or later evidence changes.
- `progress: {toolUses, turnBudget: {used, maxTurns, phase}}`: a small snapshot
  from that same identity/type-validated public `getRecord` observation. `toolUses`
  counts completed native tool-execution endings, **including unsuccessful ones**;
  it does not count starts or identify which tools ran. `used` counts successful
  native turns completed, `maxTurns` is the native turn ceiling, and `phase` is
  the explicit native enum `within`, `warned` or `exhausted`, never inferred from
  counts. Only finite nonnegative safe integers are retained, independently per
  count; missing, malformed or throwing fields become `null`, not zero. A real
  zero remains zero. An unavailable/throwing budget yields null budget fields
  without discarding a valid `toolUses` or native status. Every observation replaces
  the complete progress sample, so a failed current field cannot silently expose
  an earlier count as the deadline measurement. Returned nested objects are by
  value, not aliases to retained observations or native records.

- `latestToolEnd`: initially `null`, then only the latest **admitted ending** as
  `{tool: "read" | "edit" | "commit" | "other", isError: boolean | null}`.
  Only automatic jobs attach an ephemeral runtime-owned sink to the existing opaque
  WorkerValue reference returned by Root; explicit assignments never attach one.
  The existing child `tool_execution_end` hook first authenticates its read owner
  and exact current open, nonexpired, not-ready worker lease, then reads only
  `toolName` and `isError`. Nonstring names are ignored without reading the error;
  nonboolean errors become null. Parent admission rechecks its exact job, attempt,
  epoch, generation, healthy Root, open view and pending outcome. Each metadata
  getter and the sink boundary are fenced; throwing or reentrant metadata cannot
  overwrite a newer admitted sample or interfere with cancellation/publication.
  A commit that already set `ready` drops its ending, preserving any prior sample.
  Returned nested samples are copied by value. No starts, history, IDs, pairing,
  raw names, arguments, results, content, details or raw errors are collected.

This is partial latest-admitted-end visibility, not correlation with the native
`toolUses` counter or proof of which ending that counter measured. `isError: false`
means only a non-error ending, not a successful save, integration or learning.
It does not establish an error cause, provider RTT or commit proof. Separate-runtime
unit fixtures are not actual SDK delivery proof; the public SDK/Faux bridge
falsifier is separate evidence, and production-fixture verification remains Main's
gate. No diagnostic subscriptions, record reads, timers or pollers are added.

These counters do not prove successful reads, edits, integration, semantic learning
or provider latency. They cannot diagnose why a worker reached its deadline or
separate queue time from provider/tool time. Optional progress getter failures do
not suppress required abort/cancellation or block an otherwise valid publication.
There are no active-tool, transcript/message, usage, raw-error or read-specific
counts, and no new record reads, subscriptions, timers or polling for progress.

Public started/completed/failed events are matching-ID/type wakeups only. Each
reads the owned service record; dispatch also observes after synchronous spawn/
binding, and an authorized status may refresh the active observation once. There
is no new timer, poller, executor, retry or inference path. Synchronous events and
late old-job events cannot replace a sealed observation or the next attempt.
Before the unchanged 120-second timeout abort, deadline is sealed with the then
observed queued/running/unknown status; abort's subsequent stopped record cannot
erase it. Cancellation similarly seals before abort. Observation failure does not
suppress mandatory abort/cancellation or authorize publication. Identity, healthy
node/generation, epoch and project scope bind the observation internally; mismatch
suppresses/clears it. IDs, prompts, results, filesystem paths, corpus and native
record/event payloads are not added to this status metadata.

Both the native queue (`bypassQueue: false`) and the separate 120-second worker
view/dispatch limits, lease/readiness/revocation/branch/config/CAS/forget/review
fences remain unchanged. Local fake-clock and native-event regressions prove the
bounded source observation, including deadline evidence surviving cleanup, not an
actual deadline cause, installed adoption, provider learning or human acceptance.
No timeout increase, exact backlog diagnosis or private runtime pilot is delivered.

Forget and rollback affect only the mapped current project plus intentionally global
Core/index/procedures; other projects' deferred files are preserved. Managed ledger
version 2 stores source tombstones as `{project, source}` pairs: a project ID applies
only to that project's deferred files/episodes, and `null` applies only to global
files. Unknown or reused source IDs do not grant cross-project authority. A source
crosslinked to a global file intentionally affects that shared file, including when
another project later recovers it. Version 1 managed ledgers fail closed; this
new-root format does not automatically migrate existing roots or change the C1 store.
The full proposed ledger is reader-validated before worktree/index/HEAD mutation.

Forgetting records monotonic path/source tombstones. Global/deferred/procedure files linked
to forgotten sources are removed conservatively. For Core/index, Main first revises
the knowledge and removes that source link, preserving identity; forgetting otherwise
refuses rather than blanking identity. Rollback filters all current tombstones and
retains the current safe Core/index instead of restoring a source-forgotten version.
Stale views cannot restore forgotten paths or linked sources. Unlinked paraphrases
cannot be proven forgotten structurally; model maintenance and human privacy review
remain necessary. Old Git revisions, proposals and evidence are not secure erasure.

Every primary `before_agent_start` rereads committed Core, index and bounded
version-2 namespace/topic metadata only, not all deferred bodies or leaf names. The latest system projection replaces the
old managed block; a missing/revoked capability removes that block. Committing is
not reported as an already-updated provider request. Worker prompts are replaced
independently and never receive the primary projection automatically.

## Bounded discovery, lexical retrieval and curation (T217 source slice)

These source changes implement P0/P1/bounded P2 and the bounded P3 selection
above, not full companion parity.
T190/T213 remain completed; T217 acceptance belongs to Mahiro. They do not migrate
private config v1, ledger v2, Core/index, corpus or retained views; do not add a
sixth tool, new grants or an ABI change; and do not establish installed activation,
provider learning or human same-companion acceptance.

The public read schema and runtime parser have one owner in `retrieval.ts`:

| Arguments | Result and paging |
| --- | --- |
| `{}` | Legacy authorized file list, now validated against current state |
| `{path, offset?, limit?}` | Legacy Markdown paging, original Unicode code points, limit 1–4096 |
| `{topic: "", offset?, limit?}` | Derived namespace/count page, limit 1–32 |
| `{topic: "*", offset?, limit?}` | Discover every authorized file, including Core/index, limit 1–32 |
| `{topic: "global"}` / `"procedures"` / `"deferred/<id>"` | File page in that namespace; selects data, never project authority |
| `{query, offset?, limit?}` | Literal lexical AND search, limit 1–8 results; offset is the sorted-file scan cursor |

Selectors cannot be mixed. Paging without a selector, invalid mode-specific bounds,
unknown properties and authority selectors are rejected. Runtime additionally
checks UTF-8 bytes and lexical terms (JSON Schema length is not a UTF-8 byte bound).
A query has at most 256 UTF-8 bytes and 16 distinct word terms. Thai word segmentation
uses `Intl.Segmenter`, as existing continuity search already does. NFKC/case folding
is for matching only, never returned text or offsets. Path terms participate in AND
matching. Results are deterministic in sorted path order, not semantic relevance
scores. A late-file match yields a nearby original excerpt (at most 192 code points),
whole-file SHA-256, `path#sha256:<hash>` citation and complete source IDs. Grapheme
normalization maps back to original code-point offsets, including astral/combining
characters and case expansions. Historical quotes within maintained text remain
fallible evidence, not authenticated current preferences.

Lexical scanning is bounded to 1 MiB of file text per page, at most eight results
and 32768 serialized bytes including reserved revision-envelope space. Authority,
backing-view and current-state validation still walk the bounded view at operation
boundaries; the scan budget is not a claim about total validation I/O or hard RSS.
`complete: false` / `outcome: "incomplete"` and `nextOffset` mean coverage remains;
follow that cursor to exhaustion. `no-match` is successful exhaustion of the selected
scan suffix, not an unavailable read and not proof about earlier omitted pages.
Namespace/file pages also expose `complete` and `nextOffset`. There is no persistent
catalog/cache, embedding service, query regex execution or competing knowledge owner.

Projection preserves authored Core/index and advertises only the first eight
namespace/count entries, total authorized topic count and explicit discovery routes.
Omitted foreign namespaces remain discoverable to authenticated Primary through
`topic: ""` paging or `topic: "*"`. Scope filtering and canonical path permission
checks precede names/counts. Scoped leased/retained legacy views cannot discover
foreign names, counts, text or sources. Projection reads Core/index and immutable
ledger metadata only, never `snapshot`, `createView` or deferred Markdown bodies.
An authored stale index is preserved, not silently rewritten as a generated catalog.

All path/list/query/topic reads validate the same private view/backing files,
current config, authority and **current HEAD tombstones** before selecting results,
and recheck view/config/path authority before a final HEAD observation. Projection
uses the same ordering without deferred-body or view hydration. No validation I/O
follows that observation: a forget completed during final config/authority checks
fails closed. This is the return linearization point, not a promise to exclude a
commit made after it. An old view containing
currently forgotten paths or source-linked knowledge is unavailable as a whole:
no old text, paths, counts or citations escape and no proposal is deleted. This
minimal underlying read repair is required because integration's existing tombstone
checks alone did not protect reads. Integration/CAS/conflict recovery remains its
separate existing owner. HEAD movement through that final observation fails closed;
a previously
