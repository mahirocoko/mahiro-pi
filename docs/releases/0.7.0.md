# v0.7.0 source release record — 2026-10-25

[← Documentation](../README.md) · [Current installation](../getting-started.md)

This release separates final native execution enforcement from independently
bootstrapped feature ownership, upgrades maintained memory to a lossless tiered
engine and makes Codex Usage visibility a saved profile preference. Publication
remains distinct from installation, process replacement and human acceptance.

## Thin Root and independent feature kernel

- Root remains the final native execution boundary for lightweight secret-file
  operand checks, commit attribution and guarded RTK arguments. It no longer owns
  a dispatch allowlist or blocks ordinary tools when optional feature readiness is
  unavailable.
- `lib/kernel/` owns the shared feature registry, primary/child identity,
  generation readiness, lifecycle retirement and feature ABIs independently of
  Root. Missing kernel readiness is diagnostic rather than global tool authority.
- Named features follow effective public PSS decisions, including wildcard and
  yolo behavior. The redundant exact-DATA/provenance permission plane is retired;
  primary-session, revision, canonical-root, lease, owner-lock and private-memory
  invariants remain enforced at their actual boundaries.
- File protection is deliberately finite: recognized secret file operands plus
  four filtered configuration inspectors. It is not recursive shell-content DLP
  or a universal sandbox.

## Hybrid maintained memory and recovery

- Hybrid MemFS v2 preserves a fixed persona, durable human and project system
  tiers, references, archives, YAML descriptions, wiki-links and recency-based
  discovery while retaining legacy material losslessly.
- Scoped patch and append editing avoids whole-file rewrites. Protected shrink
  requires explicit `allowShrink` and passes the Lossless Retention Guard.
  Retained-ready drafts remain readable and correctable by the authenticated
  primary while worker-ready immutability stays runtime-owned.
- `/mh-memory`, bounded redacted `/recall`, compaction checkpoints and reinjection
  expose maintained and historical context without merging Pi, Letta or Agy
  memory stores. Historical transcript matches remain clearly UNTRUSTED.
- Explicit offline maintenance archives before mutation, preserves unknown prior
  publication outcomes and resumes only an exact retained target/revision. Large
  cold certification is completion-driven through the dedicated
  `offlineCertify` method; ordinary engine calls keep their bounded deadline.
- The supported recovery used for activation retained the archive, preserved
  memory HEAD `67998b7ffcdd1ae8b3e17eb194e7bfe0b286a4e3`, activated no proposal and
  released the maintenance barrier without claiming human acceptance.

## Performance, installation and Usage

- Memory projection batches Git object reads, uses ledger/head hot paths and
  applies bounded automatic garbage collection. RTK reuses synchronous binding
  state and bootstrap reads are size-aware while final authorization barriers
  remain intact.
- The installer migrates the owned legacy `lib/guards/bootstrap.mjs` override to
  `lib/guards/bootstrap.ts`, preserves `extensions/mahiro-worker-activity.ts` and
  still rejects unrelated required-package overrides.
- `/mh-usage codex on|off` is a strict saved profile preference. Eligible sessions
  adopt changes through bounded lifecycle checks; quota remains the explicit
  Codex CLI source with TTL, staleness, backoff and cancellation. No native-auth
  fallback or shared quota write is introduced.

## Verification and boundaries

Final source verification uses ordinary HOME with `MAHIRO_PI_TEST_MODULES` unset:
strict TypeScript covers 192 authored files with zero diagnostics; 700 source
tests report 697 pass, zero fail and three intentional skips; the genuine public
SDK suite passes 41/41. Formatting, package, documentation, immutable 17-file
provenance and `git diff --check` also pass.

Installed runtime checks observed memory ready with ABI2 and the maintenance lock
released, ordinary workflow/Code Map/RTK tools available, current managed-memory
and UNTRUSTED recall reads, and Codex Usage reported as `on (saved)` in a second
fresh eligible Pi session. These checks do not establish exhaustive rendered UI,
provider behavior, daily-use/RAM quality or human product acceptance.

The package remains `private: true` / `UNLICENSED`. This is a GitHub source release,
not npm publication or a license grant. Historical [v0.6.1 notes](0.6.1.md) remain
unchanged dated evidence; current contracts live in the linked guides.
