# v0.14.0 source release record — 2026-11-11

[← Documentation](../README.md) · [Current installation](../getting-started.md) · [RTK contract](../rtk.md)

This minor source release adds **actual upstream RTK usage statistics and a native
Pi dashboard**. Bare `/mh-rtk` now opens usage instead of notifying raw status
JSON. `/mh-rtk menu` retains mode and rewrite controls; explicit status/doctor
remain structured diagnostics without CLI execution.

## Native usage dashboard

- Overview displays tracked command count, estimated raw/filtered/saved output
  tokens and output reduction. Daily displays up to seven recent dates from the
  same JSON snapshot. The screen follows Pi's active theme.
- `1`/`2`/`3` select Overview, Daily and CLI report. `r` refreshes, `p` toggles
  project/all, arrows scroll, `m` opens controls and Escape closes. There is no
  polling or automatic mode change. Closing cancels the request; superseded
  scope results cannot overwrite the current view.
- `/mh-rtk gain [project|all]` opens the same screen. The `mh_rtk` tool's explicit
  `gain` operation returns structured evidence with bounded scope/view enums.
  Non-TUI commands do not create custom terminal UI.

## Real CLI evidence, not provider accounting

The fixed argv-only query is `rtk gain --daily --format json --text -p`; all scope
omits `-p`. Project scope means canonical cwd and descendants, not an automatically
found Git root. Tracking can include other RTK clients, not just this Pi session.
Raw/filtered/saved values are upstream **output-token estimates (bytes/4)**, not
provider input/output tokens, billed savings, dollars or native quota. Empty
tracking and unavailable data remain distinct.

RTK 1.2.0 JSON does not export command groups. Selecting CLI report explicitly
runs `rtk gain --text -p` instead of inventing groups, parsing a fragile table or
opening SQLite directly. The original static report includes its By Command
table. Optional upstream proxy sections may be global even with project scope;
they remain opaque upstream information, not Pi billing measurements. No watch,
quota, reset, provider API or raw-history request is added.

Statistics calls have independent 128 KiB JSON / 256 KiB report, three-second
and two-child bounds. Strict UTF-8/schema validation and terminal-control
sanitization reject malformed or partial evidence. Missing binary, timeout,
oversize, busy and unavailable states never fabricate zero counters. Each child
disables RTK telemetry through its environment without changing persistent
settings. Mahiro does not open the tracking database; the upstream CLI may
initialize or migrate its own storage.

## Authority and compatibility

The existing primary/feature/data/binding/state/generation/session and cancellation
checks remain current around every await. The exact fixed query needs ordinary
current PSS Bash allow and final host argument validation. A modified fixed
command is refused; late evidence is withheld after authority changes.

Automatic native off/on filtering, receipt-bound replacement approval, legacy
effective-off behavior, confirmation/CAS and no-original-retry semantics remain
unchanged. Mahiro's separate interception log stays empty. The footer remains
mode intent, not a statistics or helper-availability claim. Dependencies, patches,
immutable oracles and the 13-entry manifest order are unchanged.

## Verification and publication boundary

Focused RTK checks cover parsing, bounds, failures, permission/revocation and
stale-publication fences, native component layout, scope/refresh and disposal.
Real RTK 1.2.0 and actual Pi 1.5.2 with deterministic Faux transport were checked
in isolated profiles, including native Read/Bash/gain and wide/narrow interactive
screens. These checks do not establish real-profile activation, every OS or
human visual/product acceptance. Independent source review and the combined
release gate remain separate publication checks.

The GitHub source release includes an inspected tagged archive and SHA-256
manifest. Private profiles, memory, transcripts, runtime evidence and this
session's retrospective remain excluded. The package stays `private: true` /
`UNLICENSED`, not an npm publication or a license grant. Publication does not
install, reload the current Pi process, change mode or permissions, activate a
provider proxy, repair memory, or close human-owned tasks. A running process
needs a separately authorized reload or a newly loaded Pi instance to use the
new source.
