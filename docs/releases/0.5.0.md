## Delivered scope

- Brings the previously experimental isolated memory data engine into the standard
  explicit install path. Private per-profile ABI2 selection is separate from the
  closed memory configuration. An absent record retains ABI1; explicit off/legacy are
  preserved and invalid records fail closed. Absent-root off/legacy standard
  installation refuses before writes.
- Fresh roots receive a generic editable Companion Core: name, language, tone,
  detail and specialties. No Mahiro corpus is shipped. Root-bound edit/commit
  customizes persona; existing identity, knowledge, policy and history survive
  upgrades. Package procedural/authority guidance remains separate.
- A portable managed writer uses the installed canonical descriptor, with only
  model/thinking slots explicitly selectable through paired installer flags.
  Ordinary upgrades preserve the selected canonical route. Exact physical
  registry/availability and supported thinking are required, with explicit native
  spawn routing and no virtual, fuzzy or parent fallback. Other package role
  defaults and personal roles remain unchanged.
- `/mh-memory status` diagnoses Ready / Needs setup / Denied and merges authorized
  storage lifecycle when available. Automatic on/off, private draft, native ready,
  parent publication and next-request context activation are distinct. Unknowns
  remain unknown; local readiness is not provider execution or semantic success.
- ABI2 management adds revision/configHash-guarded `policy` for automatic admission
  only. It does not change permissions, model routes, engine selection or persona.
  Reflection remains bounded to eligible settled interactive/RPC episodes, not
  every turn or imported transcripts. Explicit assignments remain separate.
- Manual memory installation survives reflection denial. Unrelated historical
  quote-learning authority is not granted or required. Scalar-only default-deny
  removal and retained targeted restrictions are unchanged.

## Bounded policy interruption recovery

Policy attempts bind a bounded typed identity/outcome record to the actual
process-local executor and exact acquired lock. Authorized `policyOperation`
status distinguishes active/draining, retained+recoverable and unknown/unavailable,
including observed original/intended config state: abort never implies unchanged.
Fresh explicit primary `policy-reconcile` uses the status target/digest and normal
current Root/PSS, branch, HEAD/config and physical-target checks. It removes only
verified owned staging/evidence and the exact lock after actual executor drain;
it never replays/reverts config, resumes an old request or publishes corpus/Git.
Existing publication reconciliation is unchanged.

Revocation permits no cleanup. Restored authority requires the retained actual
drain reference; native same-process generations preserve it, but restart,
incomplete acquisition/cleanup, missing/corrupt evidence and ownership/state
mismatches can remain unknown and retained for explicit owner review. Durable
evidence/PIDs never prove drain, and no universal crash repair or lock stealing
is provided. Consult the maintained [policy interruption limit](../agent-memory.md#policy-interruption-limit)
for the actual API and boundaries. The aggregate independent checks include the
ordinary SDK journey; neither focused nor aggregate fixtures are activation receipts.
Direct overlapping live Root-generation policy recovery is not established by
these checks.

## Boundaries and verification

The engine isolates bounded data work in a Node child; model workers remain
in-process native Pi workers, not an OS sandbox. Canonical Root/PSS authority,
exact-root grants, native output identity, current barriers, Git hooks and logical
forgetting remain required. Existing same-operation publication reconciliation
never replays commits, steals locks or repairs orphan CAS state automatically.

Source and deterministic public SDK/Faux fixtures are not installed activation,
provider inference, semantic learning, latency/RAM improvement, full Letta parity,
rendered quality or human acceptance. No such outcomes are claimed here.
Source publication does not reload existing sessions or change auth, personal
models, permissions or themes automatically. Existing profiles require an explicit
supported upgrade and fresh runtime verification.
