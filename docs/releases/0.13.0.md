# v0.13.0 source release record — 2026-11-11

[← Documentation](../README.md) · [Current installation](../getting-started.md) · [RTK contract](../rtk.md)

This minor source release adds opt-in **RTK off/on native Bash execution**. On
uses the separately installed upstream RTK resolver and executes an authorized
supported equivalent through the native tool, returning its filtered output.
Off keeps the original command and makes no automatic RTK helper calls.

## Native filtering under current authority

- Upstream `rtk rewrite` determines supported equivalents; Mahiro Pi does not add
  another command-support whitelist. Unsupported commands stay native, and
  already-RTK commands are not wrapped twice. Direct `git commit` remains native.
- Root transforms only at final execution using the existing principal-bound PSS
  approval receipt. The original command is rechecked; changed text needs an
  independent current non-yolo allow. Original once/yolo approval, helper verdicts
  and RTK preference state never grant replacement authority.
- State/config identity, generation, cancellation and current original/candidate
  authority are fenced after resolution and again after awaited host checks.
  Native children retain their own captured principal and policy.
- Missing optional kernel/data authority, missing receipts or older PSS owners
  retain ordinary native Bash without automatic interception; they do not create
  a global Bash gate. Existing host and secret-file checks remain enforced.
- Missing, malformed or failed helpers before execution may retain the original
  through normal permission handling. Helper denial and unauthorized candidates
  block instead. Once candidate execution starts, failure or unknown outcome
  never retries the original.
- Resolver bounds remain 4,096 input bytes, 16,384 output bytes, 1,500 ms and four
  concurrent helpers. The existing Biome semantic veto remains: a proposal that
  changes Biome command meaning is not treated as an equivalent.

## Explicit activation and compatibility

Fresh profile defaults remain **off**. Legacy stored `suggest`, `rewrite-safe`
and `rewrite-rtk` values are preserved but effective off; upgrades do not silently
opt in. Explicit confirmed writes store only off/on and retain primary ownership,
public UI approval and fresh sequence/CAS checks.

Use `/mh-rtk menu` → **Mode → on → Yes** in a freshly loaded Pi process when
ready. Existing canonical-checkout registrations can load updated source in a
new process without another source copy; an already running process does not
activate new source automatically. Installation, mode selection and publication
remain separate operations. The RTK executable must already be installed by the
operator; this package does not install it or activate a provider proxy.

The footer displays the effective mode, not proven savings or helper availability.
Mahiro does not collect interception history; its log stays empty. The separately
installed RTK CLI may maintain its own tracking database. Billed savings are not
established by this release.

## Verification and publication boundary

Focused source/public-SDK checks cover resolver failures and byte bounds,
principal-bound approvals/revocation, whole-candidate chains/pipelines,
state/CAS/legacy preservation, cancellation and post-host-await final fences.
Independent high-risk review tested counterexamples rather than only successful
rewrites. Expanded verification also exercised actual RTK 1.2.0 on synthetic
commands, an isolated actual Pi TUI with public confirmation, and a fresh
installed-profile Pi with native Read/Bash/status and a real native child.
These checks do not certify every shell command, operating system, provider or
human daily-primary workflow; synthetic mode changes do not change a real profile.

Workflow store/preview test fixtures now use the existing identity-bound disposable
fixture owner and explicit cleanup, including a separate attackable inner directory.
Repeated source checks no longer retain those copied workflow fixtures.

The combined release gate and fresh final-source review are separate publication
checks. The GitHub source release includes an inspected tagged archive and SHA-256
checksum manifest. Private memory, profiles, transcripts, runtime evidence and
retrospectives are excluded. Project-local contributor skills remain outside
package resources and source archives. Public dependency pins, patches, immutable
oracles and the 13-entry manifest order are unchanged by this release.

Publication does not install, reload, turn RTK on, repair private memory locks,
change models/authentication/permissions or close human-owned tasks. The package
remains `private: true` / `UNLICENSED`, not an npm publication or license grant.
