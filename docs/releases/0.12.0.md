# v0.12.0 source release record — 2026-11-03

[← Documentation](../README.md) · [Current installation](../getting-started.md)

This minor source release aligns maintained-memory discovery, curation and the
Palace Web viewer with the current Letta Code baseline, bounds automatic
`step-count` reflection to assistant text steps within the active session, and
expands offline memory maintenance and Herdr runtime observation.

## Maintained memory and Letta parity

- Progressive directory discovery orders child entries by committed Git edit
  recency, surfaces immediate child directories and previews committed
  `<dir>/index.md` files (capped at 500 characters) without silently rendering
  the entire directory tree.
- `agent_memory_write` enforces `read_only: true` frontmatter on committed
  files during both `prepare` and `publish`, refusing body edits or frontmatter
  tampering while allowing unchanged files to remain intact.
- Reflector, writer and runtime prompts use Tiered v2 curation guidance:
  concise `system/` core files, on-demand `reference/` leaves, `<dir>/index.md`
  link upkeep and `no_changes` restraint when an episode adds no durable rule or
  preference.
- `/mh-memory help` documents the public `/mh-memory palace`, `palace close`
  and `palace json` surfaces directly.

## Reflection scheduling and offline maintenance

- Automatic `step-count` reflection counts only assistant messages with
  non-empty text (with a floor of 1 step per settled turn) so tool-only turns
  do not prematurely exhaust the 25-step threshold.
- `step-count` triggers scope `episodeBacklog` to the active session while
  `compaction` and manual `/mh-memory reflect` continue to review the broader
  backlog in chunks of at most four delivered episodes.
- `isLocallyActiveDraft` checks process liveness (`process.kill(pid, 0)`) when
  a draft specifies an owner `pid`, avoiding false lock-outs from exited
  processes that share the current root and project.
- Offline maintenance supports unlinked episode recovery, draft parking and
  restoration, and explicit `--reset` reinitialization without creating an
  automatic backup copy.

## Palace Web viewer and Herdr integration

- The immutable ABI2 Palace Web viewer (`/mh-memory palace`) follows the Letta
  Code memory-viewer layout across `Core Memory`, `External Memory`, `Context`
  and `History`, with interactive context-grid category highlighting, raw/rendered
  document toggles and diff stat bars.
- The rendered `History` commit list omits `.memory.json`-only ledger
  bookkeeping commits when Markdown commits are present, while preserving the
  underlying first-parent history verification chain.
- Herdr Web observation reports unified parent-scoped worker counts across
  supported runtimes.

## Verification and boundaries

The source is checked with Biome formatting, strict authored TypeScript,
package and documentation validation, whole-state budget accounting and focused
memory, reflection and Palace handoff suites. Source and deterministic SDK
checks do not establish provider behavior, live profile state or human visual
acceptance in every environment. Installing or upgrading this source release
still requires an intentional profile preview/apply and fresh session load.

The release archive is built from the annotated tag, inspected for private-state
paths and published with a SHA-256 manifest. This package remains
`private: true` / `UNLICENSED`; this is a GitHub source release, not npm
publication or a license grant.
