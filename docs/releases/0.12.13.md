# v0.12.13 source release record — 2026-11-08

[← Documentation](../README.md) · [Current installation](../getting-started.md)

This patch source release fixes truncated Palace file content and configured-budget
recovery deadlocks. It keeps the existing file tree and Markdown/Raw views while
replacing the installed loopback viewer with one complete offline HTML snapshot.

## Complete offline Palace

- `/mh-memory palace` exports every authorized committed Markdown body into one
  self-contained `viewers/memory-<project>.html` under the private profile root.
  Internal owner-mediated metadata/body pages bound IPC, not displayed content:
  the exported files, bodies and HTML have no viewer truncation ceiling.
- Each export atomically replaces the same private path (`0600` inside `0700`
  `viewers/`) and best-effort opens the file. There is no HTTP listener, localhost
  URL, sidecar or expiry. Exported bytes persist until replaced or removed by
  their owner. `palace close` cancels work still in progress, not existing files
  or copies already opened or saved elsewhere.
- Primary/idle identity, root binding, current authority, generation, revision,
  config, scope and forgetting checks remain enforced. The renderer receives
  certified text/metadata, never roots, Git or file readers. Public diagnostic
  DTOs retain their separate preview bounds; store and IPC safety limits remain.
- Raw retains the exact complete committed file, including YAML frontmatter,
  initial newlines and CRLF. Markdown renders the complete prose body with the
  existing frontmatter badge presentation; it is not a byte-exact source view.
  History remains the scoped, bounded offset-zero page. A typed refusal
  caused by current forgetting marks history unavailable without hiding unaffected
  files; other drift or denial fails export.

## Budget diagnostics and owner-preserving recovery

- Merged publication admission checks the complete resulting corpus against its
  configured aggregate ceiling before preparing a journal or publication plan.
  A refused proposal is retained rather than silently discarded.
- Fixed, trusted certification stages distinguish configured per-file and total
  budget failures without returning raw storage errors. The separate bounded
  `budgetRecovery` diagnostic reports configured limits and pending/lock metadata
  without exposing corpus bodies, private paths or a cleanup handle. It does not
  claim configured health or authorize a repair.
- The existing `init-project` / `migrate-v2` configuration upgrade uses the
  serialized policy owner, actual config/revision CAS, pending-operation checks,
  and authority fences. Its upgrade-only preflight observes the existing hard
  ceiling while ordinary reads, projection and publication retain configured limits.
  Automatic/reflection policy is preserved.
- Exact committed-outcome reconciliation can certify the expected tree against
  the existing recovery hard ceiling, avoiding a configured-budget deadlock.
  Proposal, tree, ledger, ancestry, clean-state and authority checks remain.
  Process-local executor diagnostics are observational only; releasing a retained
  owned lock still requires the actual sealed executor and matching nonce.
  Missing references, a restart or uncertain ownership remain owner-review cases,
  not permission to steal or delete a lock.
- Offline maintenance gates every in-root ancestor before metadata inspection,
  reusing its authority-aware read traversal while preserving the exact two-link
  marker-publication recovery seam. Denied paths are not inspected.

## Verification and publication boundary

The combined release gate and independent final-source review are recorded during
publication preparation. Earlier focused source/fixture checks and offline browser
checks covered complete bodies, tree selection, Markdown/Raw switching, export
cancellation, authority drift, configured-budget upgrades and exact-owner recovery.
Those observations are not a blanket claim about every installed profile, provider,
semantic learning outcome or human visual acceptance.

The GitHub source release includes an inspected tagged source archive and SHA-256
checksum manifest. Private memory, profiles, transcripts, snapshots, runtime evidence
and retrospective notes are excluded. Publication does not install, reload or change
models, authentication, permissions or existing private knowledge. This package
remains `private: true` / `UNLICENSED`; it is not npm publication or a license grant.
