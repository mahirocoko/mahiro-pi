# Mahiro Pi v0.3.0

[← Product](../../README.md) · [Feature guide](../README.md) ·
[GitHub release](https://github.com/mahirocoko/mahiro-pi/releases/tag/v0.3.0)

This source release combines native ownership/installation work since v0.2.0 with
memory retrieval, visible RTK state, the accepted UI scope and optional Web child
observation. It is a GitHub source release, not npm publication or an automatic
runtime/profile update.

## Highlights

- **One canonical native owner:** Root-authored guard/public dependency contracts,
  final-execution enforcement, exact session-scoped native subagents and explicit
  one-install composition with narrow feature DATA grants.
- **RTK:** bounded installed resolver proposals, original/candidate/final argument
  checks, preserved explicit off, mode status in the footer and bare command status.
  Saved Model Profiles is retired; native model/auth/defaults remain untouched.
- **Managed knowledge:** shared relevant primary knowledge across canonical
  projects with scoped workers, guarded absent-root scaffolding and preservation
  of existing Core/data. Bounded lexical query/topic discovery and compact
  curation guidance extend the existing five tools/ABI1; no new vector engine.
  Forget/late-HEAD and raw null-validation regressions have direct coverage.
- **Neko-Stack UI:** public rendering-only header/tool presentation, clean bounded
  split/word historical edit diffs, native expansion/fallback, submitted-content
  write previews and a runtime settings panel with actual-renderer samples.
- **Worker visibility:** optional counts use the existing exact native owner;
  session-opt-in Herdr Web observation emits bounded private v1 metadata.
  Compatible [Herdr Web v0.11.0](https://github.com/mahirocoko/herdr-web/releases/tag/v0.11.0)
  owns child cards and read-only details, not this producer's lifecycle.
- **Readable documentation:** product-first README, feature index and separate
  setup, UI/status, RTK, continuity, safety, utilities, Code Map, workflow,
  integration and development guides. Source archives exclude agent state.

Existing authored footer/native usage, completion voice, C1 controls, Goal,
Evidence, UX and Execution Run semantics remain with their owners.

## Deliberate limitations

- `/mh-ui` preferences are **runtime-only**, not persisted. The native host's
  `quietStartup: "header"` is separately persistent.
- Write preview has no authorized overwrite before-image; no preread or tool
  execution wrapper was added. Malformed/multi-file unsupported captured patches
  retain their original plain content rather than fabricated edit rows.
- New memory retrieval is source/Faux capability, not proof of automatic semantic
  learning, installed activation or complete companion parity. Public SDK optional
  null normalization remains distinct from raw runtime null rejection.
- The Web observer is off merely on load, POSIX-only, session-scoped and requires
  exact parent/PID/foreground and private-directory checks. Missing/stale/denied
  observation means UNKNOWN, never done/zero. No Windows live writer.
- Native direct OpenAI quota remains omitted; no borrowed credentials or new
  speculative native quota requests.
- Workflow metadata, returned navigation and recorded external checks do not
  establish execution truth or human acceptance.

## Upgrade and evidence boundaries

Follow [installation and upgrades](../getting-started.md): preserve local work,
refresh declared dependencies explicitly, preview composition and fresh-load only
the intended sessions. Version-bound provenance deliberately refuses mismatched
cached/source owners; do not work around it by widening policy.

Mahiro explicitly closed the requested UI work on 21 October 2026. That does not
claim exhaustive regular/fullscreen raster tests or acceptance of unrelated
memory/RTK/observer tasks. Web's accepted v0.11.0 consumer is separate evidence.

Release gates are fresh package/source tests, required genuine public SDK/Faux,
documentation links/coverage, scoped formatting, public host geometry, independent
review and safe archive/remote artifact verification. Their actual outcomes belong
in the published GitHub release record, not inferred from this checklist.
No new provider, auth, profile apply/reload or observer activation is performed
merely by publishing this version.
