# v0.14.1 source release record — 2026-11-12

[← Documentation](../README.md) · [Current installation](../getting-started.md) · [Maintained memory](../agent-memory.md)

This patch repairs managed-memory publication when independent primary sessions
prepare against the same HEAD. It also extends the existing explicit offline
archive transaction for retained uncertain operations. It does not reset memory,
change reflection policy or grant new permissions.

## Concurrent publication without fabricated success

A later commit can invalidate another writer's prepared HEAD before that writer
acquires the canonical lock. Previously, that failed publication could become an
unresolved journal that blocked subsequent writes across the profile.

The native executor now retains actual process-local lifecycle evidence before
the first lock-directory mutation. A sealed executor that never started that
mutation, or whose exact mkdir returned an identity-branded, operation-bound
`EEXIST`, may settle only its own ownerless operation as `not_committed_dirty`.
It does not certify another writer's outcome or remove another writer's lock.
No proposal is activated, episode reviewed or operation replayed by this failure
settlement. Post-mkdir errors and old journals without that proof remain uncertain.

## Existing archive transaction, preserved uncertainty

Explicit cooperative offline recovery now additionally supports:

- A retained terminal committed lock owner plus one independently bound ownerless
  unknown operation, including narrowly verified historical device-only identity
  drift. The terminal receipt is checked against actual committed state; stored
  identities and online ownership checks are not rewritten.
- One ownerless unknown operation without a lock whose prepared HEAD is a proven
  ancestor of a later clean, certified current HEAD. Root identity, configuration
  and the intact hash-bound ready proposal remain mandatory.

Both cases require the existing complete independent archive, exact inspection
fingerprint, authority checks and explicit reviewed crash-resume protocol. Only
bound blockers are quarantined; unknown proposals remain conflicts, not active
knowledge. HEAD, config, raw index and later committed knowledge stay unchanged.
Unrelated direct empty UUID staging directories remain untouched and archived;
nonempty, file or nested ambiguity refuses. These are not online force-unlock,
secure history erasure or hostile-process exclusion guarantees.

## Bounded diagnostics and publication boundary

`--preview --inspect-memory` reports the existing bounded operation metadata on
successful previews as well as blocker refusals. A clean Git tree alone does not
prove journals are settled. Optional observations are excluded from plan/application
authority; record bodies, corpus and raw errors remain withheld. The registered
non-reset offline operator also carries fixed, identity-branded refusal phases.

Focused disposable regressions cover pre-lock HEAD advancement, exact mkdir
contention, post-mkdir refusal, revocation, missing proof, archive/application,
interrupted resume and foreign/root/config/proposal/staging refusal controls.
Source/Faux checks do not establish every concurrent interleaving, every OS,
semantic learning quality or human acceptance. The combined `check:release` and
full source/SDK tiers are separate gates, not implied by these focused checks.

The GitHub source release includes an inspected tagged archive and SHA-256
manifest. Private profiles, memory, transcripts, runtime evidence and retrospectives
remain excluded. The package stays `private: true` / `UNLICENSED`; this is not npm
publication or a license grant. Publication alone does not install, reload sessions,
apply recovery, change models/policy, activate a provider proxy or close human-owned
product tasks.
