# v0.6.1 source release record — 2026-10-24

[← Documentation](../README.md) · [Current installation](../getting-started.md)

This patch follows the published 0.6.0 source line. It replaces per-server native
MCP tool-name admission lists with current registry/provenance and exposure
checks, while retaining the existing public permission pipeline. Publication is
not installation, process replacement or automatic human acceptance.

## Delivered scope

- Root uses a fresh public tool-registry snapshot for each call. A dispatched
  native MCP name must have exactly one current registration and the
  runtime-assigned built-in MCP owner provenance. New tools and other configured
  native MCP servers do not require another Root name-list edit.
- Names remain opaque exact identities, including native shortened/hash-suffixed
  names. Caller input, namespace aliases, copied definition metadata and an
  MCP-looking prefix do not confer native provenance or permission.
- Admission follows effective exposure: hidden, missing, withdrawn and unknown
  exposures fail closed. Direct tools require active membership; registered
  codemode/deferred tools remain nested-callable while inactive. Model-issued
  calls require active membership; model-only tools are never nested-callable.
  Nested identity comes from the host event, not caller input.
- This classification only removes the unsupported-tool veto for genuine native
  entries. It does not return a permission allow, skip PSS ask/deny, grant child
  roles tools, bypass normal codemode hooks or replace final native execution
  availability checks. There is no positive name/provenance cache.
- Required offline regressions use the actual public MCP factory with injected
  JSON-RPC and normal Faux/session dispatch. They cover new tools, another server,
  opaque long names, direct/nested policy decisions, copied foreign metadata,
  inactive/hidden tools and native withdrawal/reoffer notifications.

## Verification and activation boundaries

Final source verification includes strict authored TypeScript, formatting,
package/documentation checks, serial source tests and the required actual public
SDK/Faux suite. Existing child-control and permission regressions remain included.
These are bounded tests, not an exhaustive all-role deferred-MCP matrix or a
sandbox against hostile in-process code. Registry provenance assumes a trusted
Pi host and loaded extension set; it is not cryptographic factory attestation.

The admission change was also observed through native direct and normal codemode
read-only capabilities calls in a fresh Pi process. Matching protocol/worker
metadata is capabilities evidence, not successful browser session creation,
capture, trusted input, account isolation or product/human acceptance. No such
browser operations are established by this record.

A same-process reload banner did not establish updated transitive helper health
in the observed rollout; a fresh process restored native health. Exact loader
cache causality is not asserted, and this patch does not claim to repair Pi's
hot-reload mechanism. Follow the current [upgrade procedure](../getting-started.md#upgrade-safely):
stop on unavailable native tool health, align source/profile/dependencies and
intentionally reopen/resume only the authorized session when necessary. Never
relax guards or clear private loader state to force a smoke check through.

The ten exact package provenance pins advance to 0.6.1, not an arbitrary-version
allowance. Existing memory, targeted restrictions, Root/PSS ownership, guards-first
extension order, authored UI and native accounting are retained. A running older
package can still refuse version-bound tools until intentionally fresh-loaded.
Release permission does not authorize that runtime change.

The package remains `private: true` / `UNLICENSED`. This is a GitHub source release,
not npm publication or a license grant. Historical [0.6.0 notes](0.6.0.md) remain
unchanged dated evidence; current contracts live in the [guard guide](../guards.md)
and [development/release procedure](../development.md).
