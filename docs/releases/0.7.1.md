# v0.7.1 source release record — 2026-10-26

[← Documentation](../README.md) · [Current installation](../getting-started.md)

This patch release hardens Hybrid MemFS v2 migration and interrupted-publication
recovery at the maximum supported corpus size. It preserves the v0.7.0 thin Root,
independent feature-kernel and public-PSS ownership model while removing scale
amplification that could exhaust the ordinary publication deadline.

## Lossless migration and explicit capacity

- Legacy v1 files migrate to tiered v2 paths only after their exact original bytes
  are retained under segmented `archives/legacy-v1-<revision>/global/` or
  `archives/legacy-v1-<revision>/deferred/<project>/` paths. Project and slug remain
  separate validated path segments.
- Missing or malformed frontmatter receives deterministic safe metadata in the v2
  target without rewriting the archived source bytes. The migrated v1 originals
  are deleted only through the same prepared publication.
- Final corpus, operation delta and persisted overlay capacities are independent:
  1,024 final files, 2,049 operation changes and 2,048 overlay entries. File and
  corpus limits remain 256 KiB and 8 MiB; the ledger is 512 KiB.
- Durable operation records use an 8-MiB ceiling large enough for the bounded
  snapshots, delta, ledger copies and receipt transitions. Public status exposes
  only bounded pending-operation ID, digest, stage and record-byte metadata.
- Repeated `migrate-v2` and `init-project` calls at an unchanged revision are true
  no-ops. They return the existing revision without preparing a publication or
  accumulating retained views.

## Publication performance

- Overlay authorization is batched before immutable body hydration instead of
  performing a complete gate round-trip for each blob.
- Git blob reads use bounded `git cat-file --batch` groups and local blob-ID
  computation; discarded or irrelevant retained drafts are filtered before body
  hydration.
- Publication fences retain operation identity, current authority, revision,
  deadline and recovery boundaries without repeatedly rebuilding the full draft.
  Collision checks use bounded path batches and worktree checkpoints run at
  controlled intervals rather than once per file.
- A 1,028-change publication fixture exercises the valid transition between large
  snapshots under the ordinary 30-second engine deadline. Dedicated offline
  certification remains completion-driven and separate from interactive calls.

## Operation-bound offline recovery

- The explicit offline operator can review one exact locked `unknown` publication
  or one lockless terminal `not_committed_dirty` publication. The Git index must be
  clean and every partial tracked/untracked mutation must match the immutable
  operation plan, expected hash and size; unrelated work refuses recovery.
- Recovery archives and verifies the complete original root before restoring
  tracked paths from HEAD, removing only exact operation-owned untracked writes
  and quarantining the selected journal/CAS/staging evidence. It never replays a
  commit, steals a lock or fabricates executor quiescence.
- Resume revalidates every reviewed tracked path, applies private `0600` mode and
  fsyncs it even when Git already reports clean. This closes an interruption window
  between `git restore` and permission repair.
- Offline inventory remains finite at 131,072 entries, 8 GiB total, 256 MiB per
  file and a 64-MiB private plan. Maintenance does not automatically delete
  retained snapshots; later owner-authorized cleanup remains a separate destructive
  operation with fresh HEAD, Git and doctor verification.

## Verification and boundaries

Final source verification uses ordinary HOME with `MAHIRO_PI_TEST_MODULES` unset:
strict TypeScript and formatting pass; 709 source tests report 706 pass, zero fail
and three intentional skips; the genuine public SDK suite passes 41/41.
Documentation, package validation, immutable 17-file provenance and
`git diff --check` also pass. A fresh independent verifier reports no medium/high
findings on the final release diff.

Installed verification migrated a reviewed legacy corpus without dropping Git
history, private views or retained conflicts. All 286 legacy source files matched
their segmented archives byte-for-byte, no v1 originals or missing v2 targets
remained, repeated migration/initialization became no-ops and doctor reported
`Ready` with 577 files and no pending operation or retained lock. A separately
authorized local cleanup then removed three obsolete maintenance snapshots while
preserving the same memory HEAD, clean Git state and healthy doctor. These installed
observations do not imply automatic snapshot retention policy, provider behavior,
rendered quality, daily-use/RAM acceptance or human product acceptance.

The package remains `private: true` / `UNLICENSED`. This is a GitHub source release,
not npm publication or a license grant. Historical [v0.7.0 notes](0.7.0.md) remain
unchanged dated evidence; current contracts live in the linked guides.
