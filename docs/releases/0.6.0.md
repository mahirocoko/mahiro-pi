# v0.6.0 source release record — 2026-10-24

[← Documentation](../README.md) · [Current installation](../getting-started.md)

This dated source record describes version 0.6.0, following the published 0.5.0
source line. It adds workflow presentation, task-adoption guidance and cached usage
surfaces while retaining canonical state owners and existing authority boundaries.
Publication is not installation, a session reload or automatic human acceptance.

## Delivered scope

- Natural multi-step task guidance reuses branch-local session steps without
  creating tasks automatically. Completed-only steps no longer crowd the widget.
  Session steps remain distinct from the cross-session task board and acceptance.
- Readable tool cards expose captured pending/result states through public TUI
  geometry, including the Tasks owner's own geometry lifecycle. Captured results
  are not execution receipts or human acceptance merely because they render well.
- `/mh` discovers available canonical owners and delegates navigation to their
  callbacks. Last-observed contextual attention consumes authorized structured
  results only; it does not poll another store, execute workers or complete Goals.
  Exact manager/session/CWD and generation retirement fence stale callbacks.
- `/mh-usage` provides bounded, cache-only pages for native session totals, context,
  quota windows, resets and balances. Runtime display preferences and the transient
  panel do not reset accounting or persist source-selection changes.
- The footer uses pipe-separated semantic groups and ten-cell `▰` / `▱` bars.
  Context USED precedes supported Codex quota LEFT inline where space permits.
  Narrow layouts retain known quota percentages on additional semantic rows.
  Secondary file counts, thinking and empty cells preserve the authored hierarchy;
  model/branch accents, semantic filled bars and native totals remain distinct.
- Green `+N` and red `−N` are net tracked textual line changes against HEAD,
  including staged and unstaged changes, not untracked-file counts. `?N` and `~N`
  remain file counts. Bounded sequential local Git collection disables external
  diff/textconv, never fetches and preserves unknown binary/unborn/error totals.

## Explicit read-only Codex CLI quota

The Pi source remains the default. `/mh-usage source codex-cli` explicitly selects
an existing supported CLI login; `/mh-usage source pi` returns to Pi. Selection is
runtime-only, independent of the model's provider, and never a silent fallback.
The usage inspector identifies the CLI source; the compact footer labels actual
windows. Its account may differ from Pi's account. Native direct OpenAI quota and
native credential lookup remain omitted.

Collection requires current primary TUI/Root ownership and effective public PSS
file authority. Targeted denial, ask, missing service or path restrictions veto
access. The fixed supported token-file layout is bounded by file/owner/mode checks
and an FD-associated pathname observation before content read. That observation
is not an immutable namespace lock or a concurrent-content guarantee; unsupported
or ambiguous observations fail closed. Network collection is a bounded fixed-endpoint
GET without redirects, with cancellation, cache/stale/backoff and identity fences.
There is no login refresh, CLI/keychain invocation, API-key fallback, auth-file write
or credential/account/raw-response projection. CLI quota never publishes or clears
Herdr's shared native quota slots. See [status and usage](../status.md) for the
supported format and limits.

## Verification and boundaries

Pre-release verification includes strict authored TypeScript, formatting, package
and documentation gates, source tests, the required genuine public SDK/Faux suite
and explicitly supplied public TUI geometry. Independent plaintext comparisons
cover widths 1–160 and Thai/RTL/ZWJ/control inputs; ANSI checks cover secondary
roles, thresholds and identity-like text. These are bounded checks, not a claim
that every possible native terminal width or every workflow was human-tested.

Actual wide-terminal output independently confirmed readable task cards and the
current footer/CLI details. Narrow-terminal readability has synthetic public
geometry evidence, separate from native-wide output. UI observation, deterministic
SDK fixtures and source publication do not establish provider efficacy, memory
learning quality, RAM improvement, daily-primary acceptance or complete parity
with another agent product. Unknown and stale outcomes remain explicit.

Existing memory, Root/PSS policy, revision gates, guards-first extension order,
Neko-Stack identity and native usage accounting are retained. The exact package
provenance pins advance to this version, not an arbitrary-version allowance.
Supported upgrades remain explicit; source publication does not change auth,
profiles, models, permissions or themes and does not reload an active session.
