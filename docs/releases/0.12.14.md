# v0.12.14 source release record — 2026-11-11

[← Documentation](../README.md) · [Current installation](../getting-started.md)

This patch source release refreshes the public Pi/PSS/subagent dependency set and
fixes installed package references that could become invalid during dependency
replacement. Existing native guard enforcement and authority boundaries remain.

## Reviewed dependency refresh

- Exact development/test pins for public Pi coding-agent, AI and TUI packages move
  to **1.5.2**. The declared peer floor remains **≥1.3.0**; this is not a fresh
  minimum-version certification. Pi 1.5.2's idle cache-warming default may incur
  provider usage; installation does not silently change the profile's policy.
- PSS moves to **42.0.0** with the authored aggregate Bash approval binding,
  revocation and matched-surface attribution patch preserved.
- Subagents moves to **25.0.5** with the authored session/manager ownership,
  creator-owned child controls and initial outcome-claim patch preserved.
- Installer validation follows the upstream 1,000-entry configuration ceilings,
  including prompt notifications. The conservative installer subset still refuses
  unsupported command-effects configuration without changing it.
- Public-supply fixtures follow the new package layouts. Patch-touched-file
  hashes describe reviewed patch state, not complete dependency provenance.

## Stable installed references and truthful diagnostics

- Explicit installation registers PSS and Subagents through the declared
  `node_modules/@gotgenes/…` locators rather than transient pnpm store realpaths.
  Preview and apply still validate and bind the resolved physical owner identities
  and required patch capabilities.
- Subagents' child-extension exclusion follows that same exact configured source
  string. Unrelated declarations and required permission/Root presence in children
  are preserved; unknown stale or conflicting sources still require explicit review.
- The explicit offline-maintenance CLI recognizes those declared locators or
  their exact current physical owners; it still loads canonical owners in the
  guarded native subprocess and refuses unrelated aliases.
- Existing profiles with stale physical paths require an explicitly authorized,
  backed-up reference repair. Source loading and startup do not rewrite profiles.
- Availability diagnostics run after all session-start handlers, including PSS
  publication. A missing PSS service reports that native tools fail closed; a
  kernel-only failure with PSS active remains diagnostic, not a global native-tool
  gate. No guard is disabled and no permission is widened to recover availability.

## Verification and publication boundary

Focused regressions exercise replacement of a disposable dependency owner while
saved locators remain usable, byte-idempotent installation, exact child exclusions,
late PSS publication, and native Root behavior with PSS present or absent. Public
SDK/Faux tests use isolated public-package supplies, not provider inference.
A separately authorized actual Pi startup and native Read/Bash, feature-status and
native child smoke also succeeded; that bounded check does not certify every
profile, provider or human daily-primary workflow.

Combined release checks and independent final-source review remain publication
gates. They do not establish universal installed compatibility, model quality,
memory semantics or human visual/RAM acceptance. Contributor rules now explicitly
require installed-readiness evidence for runtime-affecting updates rather than
source-test success alone.

The GitHub source release includes an inspected tagged archive and SHA-256 checksum
manifest. Private memory, profiles, transcripts, snapshots, runtime evidence and
retrospectives are excluded; project-local contributor skills are not package
resources. Publication does not install, reload, synchronize skills or change
models, authentication, permissions or existing private knowledge. The package
remains `private: true` / `UNLICENSED`, not an npm publication or license grant.
