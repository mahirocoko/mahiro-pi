# v0.12.5 source release record — 2026-11-04

[← Documentation](../README.md) · [Current installation](../getting-started.md)

This patch source release prepares right-aligned extension footer statuses and
corrects current documentation to match existing permission, maintained-memory,
RTK and integration ownership. The documentation corrections do not add runtime
authority or change installation defaults.

## Right-aligned extension footer statuses

- `lib/footer.ts` retains other extensions' status cells once, sorts them by key
  and packs them as a right-aligned group. When space permits, the first packed
  status row shares the first usage row beneath the model/thinking area, with at
  least three columns of separation. Remaining rows stay right-aligned below the
  core fields.
- `test/footer.test.ts` and `check-geometry.ts` add coverage for the shared-row
  layout and narrow-width wrapping without dropping status text.
- `docs/status.md` describes the placement and wrapping behavior.

## Current guide corrections

- The README describes RTK as explicit, non-executing rewrite previews without
  automatic Bash interception, and distinguishes one-time profile setup for
  private Web receipts from session opt-in.
- Installation, bootstrap and UI guides clarify kernel-owned appearance access,
  public PSS/native execution authority, canonical package registration and the
  ABI2 writer's separate 240-second lease and bounded publication reserve.
- Memory and agent guides correct reflection step counting and retry backoff,
  and distinguish historical R2/R7 evidence labels from the current direct-upstream
  maintenance direction. Source availability does not establish installed
  activation or human acceptance.
- Development guidance aligns package validation and version references without
  changing immutable upstream oracle hashes or treating them as runtime grants.
